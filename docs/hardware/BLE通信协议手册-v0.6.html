1.0 通信协议概要与链路规范

AI 智能头盔主控采用全志 V821 高集成机器视觉 SoC 单芯片方案（原生板载 SiP 集成 2.4GHz Wi-Fi 4 与 BLE 5.0 复合射频基带，运行 Tina Linux 嵌入式系统），外围搭载毫米波雷达、6 轴 IMU 姿态传感器、GPS/北斗双模定位模组以及蜂鸣器、照明大灯、SOS 物理按键等硬件。

头盔与手机 App 之间通过低功耗蓝牙（BLE）进行原生点对点 GATT 通信：

  • GATT 角色：头盔为 GATT Server（从机 / 外设），手机 App 为 GATT Client（主机 / 中心设备）。
  • 广播规则：广播名称为 Helmet-<deviceId后6位>（例如 Helmet-94173f），广播间隔 100 ms。
  • 配对安全：采用 Just Works 模式快速配对，无需 PIN 码交互。
  • 服务与特征值 UUID：
    • 通信服务 UUID：0000FEE0-0000-1000-8000-00805F9B34FB
    • 特征值 A（事件上行与应答）：0000FEE1-0000-1000-8000-00805F9B34FB，属性为 Notify。头盔向 App 推送状态回执、实时事件包与离线补传包。
    • 特征值 B（指令下行与确认）：0000FEE2-0000-1000-8000-00805F9B34FB，属性为 Write / Write Without Response。App 向头盔下发控制、配置及事件 ACK。
  • MTU 与分帧机制：连接建立后由 App 协商 MTU 至 247 字节（有效单包载荷上限 244 字节）。本协议所有指令及事件单包均在 4～25 字节之间，完全落入单包传输窗口，无封包与粘包开销。
  • 字节序：除特别说明外，所有多字节数值（int16, uint16, int32, uint32）统一采用低字节在前、高字节在后的小端序（Little-Endian）。

1.1 下行指令包格式 (App → 头盔 特征值 B Write)

手机 App 向头盔下发控制指令、配置写入或查询时，报文结构如下：

指令码 (Instruction) 流水号 (Seq) 操作参数 (Parameters)
Instruction (1B) Seq (1B) Parameter 1 ... Parameter N

指令码：1 字节，定义当前请求类型（如 0x02 读寄存器、0x03 写寄存器、0x04 对时等）。

流水号：1 字节（0x00～0xFF），由 App 发起自增；头盔应答时原样返回该序号，用于 App 端异步回调匹配。

操作参数：N 字节，根据具体指令类型确定内容。

1.2 上回应答包格式 (头盔 → App 特征值 A Notify)

头盔对下行指令处理完毕后返回的应答报文结构如下：

应答指令码 (Resp_Ins) 对应流水号 (Seq) 执行状态 (ERROR) 返回数据 (Data)
Resp_Ins (1B) Seq (1B) ERROR (1B) Data 1 ... Data N (可选)

应答指令码：等于触发该应答的原下行指令码。

对应流水号：原样返回 App 下发时的 Seq。

执行状态：1 字节 ERROR，为 0X00 表示成功无错；非零表示具体错误码（详见 3.0 节）。

返回数据：读指令返回实际数据，其他指令可为空。

1.3 主动事件上报与确认格式 (EVENT & ACK)

头盔发生安全事件、周期位置更新或状态心跳时，主动推送事件报文；App 接收并校验后对高危事件回复确认报文：

1. 头盔主动推送事件帧结构 (头盔 → 特征值 A Notify)：

指令码 事件代码 (Event_Code) 事件流水号 (Event_Seq) UTC 时间戳 (Timestamp) 事件具体载荷 (Payload)
0X05 Event_Code (1B) Event_Seq (4B, uint32) Timestamp (4B, uint32) Payload 1 ... Payload N
  • 指令码：固定为 0X05。
  • 事件代码：1 字节，定义当前事件类别（0x01:跌倒, 0x02:SOS, 0x03:碰撞, 0x04:障碍, 0x05:解除, 0x06:定位, 0x07:心跳）。
  • 事件流水号 (Event_Seq)：4 字节 uint32 小端，单调递增，掉电保持连续性（采用步长预分配机制，开机从 Flash 读基值后预加 1000 写回，运行期 RAM 原子自增，兼顾防回绕去重与 Flash 寿命保护）。App 据此配合 deviceId 构造云端全局唯一 eventId。
  • UTC 时间戳 (Timestamp)：4 字节 uint32 小端，标准 Unix 秒级时间戳。若系统未校时则填充 0X00000000，由云端根据接收时间兜底补正。

2. App 确认回执结构 (App → 特征值 B Write)：

确认指令码 (ACK) 对应事件代码 对应事件流水号 (Event_Seq) 处理状态 (Status)
0X06 Event_Code (1B) Event_Seq (4B, uint32) 0X00 (1B)

头盔发出高危事件后启动 1500 ms 计时器，若超时未收到 ACK 则自动重发，连续重试 3 次未果判定为离线，转入本地 Flash 保护队列。

1.4 业务指令集汇总

指令名称 功能说明 指令码 参数构成
PING 查询头盔运行工作状态与自检健康度 0x01 无
READ DATA 从头盔内存控制表读取参数 0x02 首地址(1B) + 长度(1B)

1.4.5 事件主动上报指令 EVENT REPORT

每条事件均统一遵循如下报文封装头：

[0x05][Event_Code 1B][Event_Seq 4B][Timestamp 4B][业务载荷 NB]

各事件业务载荷详细规范表：

事件代码 事件类型标识 载荷字节 载荷字段内部布局定义 触发属性
0X01 possible_fall (跌倒报警) 11 字节 置信度(1B, 0~100%) + 冲击力(1B, 0.1g) + 倾角(1B, 度) + 纬度快照(4B, int32) + 经度快照(4B, int32) 高危 (必ACK)
0X02 manual_sos (手动求救) 11 字节 触发方式(1B: 1长按/2双击) + 按键时长(2B, uint16 ms) + 纬度快照(4B, int32) + 经度快照(4B, int32) 高危 (必ACK)
0X03 collision_risk (碰撞风险) 15 字节 风险等级(1B: 1低/2中/3高) + 目标类型(1B: 0未知/1车/2人/3障碍) + 方向(1B: 1前/2后/3左/4右) + 目标距离(2B, uint16, 0.1m, 最大6553.5m) + 预测TTC(1B, uint8, 0.1s) + 逼近速度(1B, uint8, km/h) + 纬度快照(4B) + 经度快照(4B) 高危 (必ACK)
0X04 obstacle_risk (前方障碍) 15 字节 高危 (必ACK)
0X05 risk_cleared (风险解除) 4 字节 被解除的那条风险事件的 Event_Seq (4B, uint32)；全 0 表示清除全部风险 通知
0X06 location_update (位置更新) 15 字节 纬度(4B, int32, WGS-84) + 经度(4B, int32, WGS-84) + 地速(2B, uint16, 0.1m/s) + 航向(2B, uint16, 0.1°, 无效0xFFFF) + 水平精度(1B, uint8, m, 无定位0xFF) + 海拔(2B, int16, 1m, 覆盖全球, 无效0x7FFF) 周期 (5s/30s)
0X07 device_status (状态心跳) 2 字节 电池电量(1B, 0~100%) + 充电状态(1B: 0未充/1充电中) 周期 (60s)

1.4.8 离线数据补传读取指令 RESEND DATA

功能按偏移请求读取离线事件记录
指令0X08
参数 1起始偏移序号 (2 字节 uint16)
参数 2请求读取条数 (1 字节 uint8)

补传交互与清除时序机制：

  1. App 发送读取请求，如请求读取 3 条：08 07 00 00 03；
  2. 头盔依次将该 3 条事件以独立 Notify 事件包（指令码 0x05）推送至特征值 A，报文结构与实时事件完全相同；
  3. 推送完毕后，头盔发送一条 0x08 结束应答包：08 07 00 03（携带实际推送条数 3）；
  4. App 收到每条事件包后，照常向特征值 B 发送 EVENT ACK (0x06)；头盔收到对应 Event_Seq 的 ACK 后，即刻从本地存储中标记擦除，避免重复拉取。

0X34 事件累计流水基数 (Event_Seq Base) 4 R 是 0X00000000 4字节 uint32 小端。开机从 Flash 读出后预分配加 1000 写回，运行期间 RAM 单调累加，永不回绕
0X40 设备 ID 字符串 (deviceId) 16 R/W 是 ASCII 例如 helmet_94173f，产线单次烧写并加锁保护，不足补 0x00
0X50 设备通信密钥 (deviceSecret) 32 W (只写不可读) 是 ASCII 产线写入，仅供系统内部存储，预留 4G 扩展鉴权，BLE 读操作被拒绝

3.0 工作状态与错误代码对照表 (ERROR)

错误码 (Hex) 错误标识符号 原因说明 处理建议
0X00 STATUS_OK 执行成功，无任何错误 正常解析后续数据
0X01 ERR_LENGTH 数据包长度与指令定义不符 核查待发送的字节总长
0X02 ERR_INSTRUCTION 未定义的非法功能指令码 核对 1.4 节指令列表
0X03 ERR_ADDR_RANGE 访问的内存控制表首地址超界 核对 2.0 节寄存器地址
0X04 ERR_EPROM_LOCKED 内存表处于只读锁保护态 (0X08=1)，禁止写入 先向 0X08 写入 0 解锁
0X05 ERR_PARAM_VALUE 参数写入数值超出物理有效范围 校验参数合法取值范围
0X06 ERR_BATTERY_LOW 当前电量过低 (<15%)，高功耗操作被拒绝 提醒用户连接充电线
0X07 ERR_HARDWARE_FAULT 对应硬件外设（雷达/IMU/GPS）通信失联 提示传感器硬件自检异常

4.0 系统运行周期与通信时序规范全表

为保障嵌入式芯片低功耗运行、避免无线信道拥塞，并确保高危安全事件微秒级送达，整机通信时序与各业务周期规范如下表：

时序 / 周期参数项 设定值 / 周期 触发源 / 判定条件 适用场景与详细工程说明
运动状态定位周期 5 秒 (5s) 定时器 / 骑行运动态 IMU 检测到运动（速度 > 1 m/s 或持续震动），每 5s 通过特征值 A 上报一次位置（0x06）
静止节能定位周期 30 秒 (30s) 定时器 / 停车静止态 停车等待或熄火，连续静止超过 3 分钟 (180s) 自动降频至 30s 节能；检测到运动瞬间恢复 5s 周期
心跳状态上报周期 60 秒 (60s) 定时器周期触发 每 60s 上报一次电池电量、充电状态及健康度（0x07）
蓝牙广播间隔 (Adv) 100 毫秒 (100ms) 射频底层周期 开机或物理断开后广播 Helmet-xxxxxx，兼顾秒级快连与待机省电
连接间隔 (Conn Int) 20ms ～ 40ms App 协商参数 确保高危告警从算法触发到送达手机端时延 < 50ms
监控超时 (Timeout) 5000 毫秒 (5s) 底层链路监控 连续 5 秒未收到底层 PDU 交互，双方判定物理链路断开，头盔恢复广播，App 后台重连
高危事件 ACK 等待超时 1500 毫秒 (1.5s) 软件重传定时器 跌倒、SOS、碰撞、障碍事件发出后等待 App 的 0x06 ACK 响应
高危事件最大重传次数 3 次 累计重传计数 连续 3 次（共 4.5s）超时未收到 ACK 或此时蓝牙已断，事件立即压入 Flash 保护队列
毫米波雷达防碰撞去抖 2.0 秒 (2s) 算法多目标追踪 同一逼近目标连续追踪期间不重复发告警，仅危险等级升级时更新；脱离危险区持续 2s 稳定后发一条风险解除（0x05）
物理 SOS 长按判定阈值 2.0 秒 (2000ms) 物理按键硬件中断 持续按压 $\ge 2000\text{ ms}$ 判定为有效手动求救，过滤短按防误触
离线补发流控间隔 30ms ～ 50ms 补传流控延时 避免突发打满 BLE 协议栈缓冲区；头盔推一条、App 回一条 ACK，收到 ACK 物理擦除
Flash 离线缓存容量 ≥ 1000 条 (最长 48h) SPI NOR Flash 环形区 两级存储区：高危事件保护区永久保留（严禁覆盖）；常规心跳与位置 FIFO 覆盖
硬件 RTC 晶振漂移指标 < 1.5 秒 / 天 32.768kHz 工业晶振 离线无网络时保证全天事件时间戳物理误差在 2 秒以内

4.3 突发高危安全告警与确认闭环时序

发生摔倒、手动 SOS 或碰撞危险时，头盔本地立刻声光警报，并通过 BLE 上报，双向必须通过 ACK 闭环：

sequenceDiagram
    autonumber
    actor Car as 后方来车
    participant Helmet as 头盔主控 V821
    participant App as 手机 App
    participant Cloud as 云端后端
    actor Family as 紧急联系人

    Car->>Helmet: 毫米波雷达检测到汽车高速逼近 (TTC < 1.8s)
    Helmet->>Helmet: 触发本地蜂鸣器急促报警 + 振动马达提示骑手
    
    Helmet->>App: Notify 碰撞预警包 [0x05][0x03][Seq=101][UTC 4B][高风险/车/12.5m/附带经纬度]
    activate Helmet
    Helmet->>Helmet: 启动 1500ms 本地 ACK 等待定时器

    App->>Helmet: Write 确认回执 [0x06][0x03][Seq=101 4B][Status=0x00]
    deactivate Helmet
    Helmet->>Helmet: 收到对应 Seq=101 的 ACK，取消定时器，确认妥投
    
    par App 中转报警
        App->>Cloud: 立即上报碰撞风险 (附带真实发生时间与出事地点)
    and App 界面交互
        App->>App: 手机全屏爆红闪烁预警 + 语音播报“后方有车！”
    end

    opt 若 1500ms 超时未收到 ACK
        Helmet->>App: 自动重发第 1 次 [0x05][0x03][Seq=101]...
        note over Helmet: 连续重试 3 次均超时，立即将事件压入 Flash 离线保护队列
    end

4.4 离线断连、本地暂存与重连补传时序

无信号或手机离体断连时，头盔本地 Flash 安全队列暂存事故记录；蓝牙重连后逐条补传并逐条物理擦除：

sequenceDiagram
    autonumber
    participant Helmet as 头盔主控 V821
    participant Flash as 板载 Flash 环形区
    participant App as 手机 App
    participant Cloud as 云端后端

    note over Helmet, App: 距离过远或 App 异常杀死，蓝牙物理链路断开 (Disconnected)
    
    rect rgb(255, 235, 235)
        note over Helmet: 骑手在断连期间发生摔倒！
        Helmet->>Helmet: 算法判定跌倒，生成事件 Seq=102，记录当前 UTC 时间 T1
        Helmet->>Flash: 写入高危保护队列 (掉电不丢失，永不覆盖)
    end

    note over Helmet, App: 骑手拿出手机打开 App，BLE 重新握手成功 (Connected)

    App->>Helmet: 发送查询离线数据指令 [0x07][Seq=01]
    Helmet-->>App: 返回未上报离线条数 = 1 [0x07][Seq=01][Status=0][0x01 0x00]

    App->>Helmet: 发送拉取数据指令 [0x08][Seq=02][偏移 0x0000][读取条数 0x01]
    
    rect rgb(240, 255, 240)
        note over Helmet, App: 逐条补传与逐条 ACK 闭环
        Helmet->>App: Notify 补发摔倒记录 [0x05][0x01][Seq=102][时间=T1][置信度/冲击力/经纬度]
        Helmet->>App: Notify 发送拉取结束标记帧 [0x08][Seq=02][Status=0][实际完成 0x01]
        
        App->>Helmet: Write 回执 ACK [0x06][0x01][Seq=102 4B][0x00]
        Helmet->>Flash: 收到 Seq=102 ACK，物理标记擦除该条记录 (防止重复拉取)
    end

    App->>Cloud: 将历史补传摔倒事件发往云端 (明确标明发生时间为 T1)
    Cloud->>Cloud: 云端按原始发生时间 T1 还原现场，不会被当成新事故重复误报
