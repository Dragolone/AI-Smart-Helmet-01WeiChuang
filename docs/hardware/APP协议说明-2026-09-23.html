1.0 协议概要

APP 对接两条通道，互不替代：

通道干什么APP 按什么做
Wi-Fi + RTSP 实时彩色视频 本文第 2、3 节
BLE GATT 握手、状态、配置、跌倒 / SOS / 雷达告警 BLE 手册 v0.6，本文第 4 节只列入口

蓝牙不传视频。不要用 HTTP 抓图、网页 MJPEG、HLS、WebView 播 RTSP，也不要自研一套拼帧协议。

2.0 视频协议

2.1 固定参数

真机时头盔是热点，手机连上去拉流。参数写死，不要做发现、不要加账号。

项值
热点 SSIDX821cam
热点密码Aa123456（WPA2，2.4 GHz）
头盔 IP192.168.176.1
拉流地址rtsp://192.168.176.1:8554/ch0
端口8554（不是 554）
编码H.264（AVC），彩色，无音频
分辨率 / 帧率1280×720，目标 30 fps
传输RTSP over TCP（RTP 嵌在同一条连接里）
鉴权无。不要写成 rtsp://user:pass@...

无板子联调时，只把主机改成电脑 IP，路径和端口保持 :8554/ch0，见第 3 节。

2.2 拉流流程

播放器会做下面这套会话。自研才需要手写；用现成播放器时，只要打开同一 URL，并强制 TCP。

OPTIONS rtsp://<host>:8554/ch0 DESCRIBE Accept: application/sdp SETUP Transport: RTP/AVP/TCP;unicast;interleaved=0-1 PLAY 信道 0 收 H.264 RTP，信道 1 收 RTCP TEARDOWN 离开预览页必须发，不要空挂会话

SDP 里应有 H.264、clockrate=90000。SPS/PPS 可能在 SDP，也可能只在码流里，两种都要能出第一帧。

2.3 APP 如何出画

  1. 连上头盔热点后，把该 Wi-Fi 绑到本进程（Android 必须 bindProcessToNetwork，否则会走 4G，表现为已连热点但黑屏超时）。
  2. 打开 rtsp://192.168.176.1:8554/ch0，transport 指定 TCP。
  3. H.264 硬解，解码帧直接铺到 Surface / UIView，按 16:9 全屏或留黑边。
  4. 关掉播放器自带的进度条、文件名、音量条。本阶段无音频。
  5. 首帧前显示「正在连接」；约 5 秒无画面则提示检查 Wi-Fi。
  6. 进后台：停播并 TEARDOWN。回前台重新 PLAY。
  7. 截图从解码器取一帧，不要再向头盔要 JPEG。

延迟按局域网 TCP RTSP 的 200～800 ms 来预期即可。

3.0 无硬件怎么测视频

APP 组没有头盔时，用电脑起一个和真机相同的 RTSP：端口 8554、路径 /ch0、H.264、720p30、TCP。APP 只改主机 IP，播放逻辑不用改。

环境拉流地址
真机头盔rtsp://192.168.176.1:8554/ch0
无硬件（电脑模拟）rtsp://<电脑局域网IP>:8554/ch0

电脑上：解压 AI头盔-APP无硬件测试包.zip，先装 ffmpeg（winget install Gyan.FFmpeg），再双击 启动测试流.bat。

脚本会打印本机 IP 和完整 URL。先在同一台电脑用 VLC 打开该 URL，选项加 :rtsp-tcp，能看到彩条 / 时间戳测试图，再拿手机 APP 播。

手机上：手机和电脑连同一个普通 Wi-Fi（家里路由即可，不必等头盔热点）。APP 里把主机改成脚本打印的 IP，其余参数不变，强制 TCP。

没有脚本时，等价命令：

ffmpeg -re -f lavfi -i testsrc=size=1280x720:rate=30 -c:v libx264 -pix_fmt yuv420p -preset ultrafast -tune zerolatency -g 30 -bf 0 -f rtsp -rtsp_flags listen -rtsp_transport tcp rtsp://0.0.0.0:8554/ch0

ffmpeg 监听模式一次只接一个客户端。关掉 VLC 再开 APP。要多人同时看，改用 MediaMTX 在 8554 收流。

电脑 VLC 能出画、APP 不能：查 TCP 是否打开、Android 是否绑错网、手机和电脑是否同一网段。电脑也不能：先把模拟器拉起来，不要先改 APP 协议。

4.0 控制协议（BLE）

字段、寄存器、时序图以 《AI智能头盔通信协议手册》v0.6 为准，不要另写 JSON 或 Nordic UART。

项值
广播名Helmet-<deviceId 后 6 位>，如 Helmet-94173f
服务0000FEE0-0000-1000-8000-00805F9B34FB
上行 Notify0000FEE1-0000-1000-8000-00805F9B34FB
下行 Write0000FEE2-0000-1000-8000-00805F9B34FB
MTU连上后协商 247
字节序小端

开机必须按这次序：MTU → 打开 FEE1 Notify → 读 deviceId → 对时 → 查离线。跌倒 / SOS / 碰撞 / 障碍必须在 1500 ms 内回 0x06 ACK。位置和心跳只展示或上云，不 ACK。

无头盔时：按手册把组包、解包、ACK、控制表先写成代码，用单元测试对十六进制例子。不要用调试口 aw-ble-test-007 / Nordic UART 当产品协议。

5.0 APP 对接流程

  1. 没有板子：先用第 3 节模拟器把播放页做完（出画、后台停播、重连）。
  2. 有板子：扫并连接 Helmet-*，按手册做完握手五步。
  3. 提示用户连 X821cam / Aa123456，进程绑定该网络。
  4. 播放 rtsp://192.168.176.1:8554/ch0，强制 TCP，硬解铺满。
  5. 预览时继续收 BLE Notify；高危事件立刻 ACK，告警叠在画面上。

真机热点没有互联网，登录和地图不要在预览页访问外网。iOS 可能弹「无互联网是否仍用」，文案写明此时没有网是正常的。
