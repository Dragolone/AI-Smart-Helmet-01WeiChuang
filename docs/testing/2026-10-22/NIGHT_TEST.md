## 三、观察项（不改，进优化清单 / B 线）

- **运行中改时区**：显示的时刻跟新时区，但「今天 / 昨天」分组、今日骑行的零点仍按旧时区，重启 App 才对（JS 引擎的本地日期方法停在进程启动时的时区）。约 20 处日期计算，求救不受影响 → 优化清单 4。
- 时间错得很离谱时，正式环境整个 App 会是「网络连接失败」（HTTPS 证书校验），不提示「手机时间不对」→ 优化清单 5。
- 地图页位置更新逐条重画（离线积压一次性补传时会卡一阵）→ 优化清单 6。
- 积压补传每 5 秒 100 条，1000 条约 50 秒，可以连续冲刷 → 优化清单 7。
- 显示层不校验：后端出错时会写出「—%」「undefined 位成员」「-50%」、把字符串 "no" 当成「充电中」→ 优化清单 8。
- 频道满员提示写死「最多 20 人」，后端上限可配 → 优化清单 9。
- **系统语言是维吾尔 / 藏 / 蒙古等国内少数民族语言时**，按 O11 退回英文；这部分用户多半读简体比读英文顺 → 待你定 O33（手测清单第四节）。
- 设置页（安全检测与预警等）对不存在的头盔仍画出整张开关表单（顶上一行红字「未找到该头盔」），设备详情页是干净的空态 → 优化清单 10。
- 服务端截止后约 5 秒内（扫描间隔）仍接受取消（只看状态不看截止时间）→ 上线清单 B 线 25 定口径。
- 本地后端不提供 `/legal/*`（云端由网关托管），本地包里协议页打不开是环境问题。
- 两顶头盔同时有进行中的求救时，两条求救通知被安卓自动收成一组：锁屏 / 通知栏上要先展开组、再展开那一条才看得到「我没事，取消」→ 优化清单 11。
- B 线：接口应答统一加 `Cache-Control: no-store`；每账号频道数没有上限；紧急联系人服务端不拦本人号码 / 重复号码（App 端拦了）→ 上线清单 B 线 22、23。
