## 4. SOS 与数据可靠性：最高优先级

验证 possible_fall/manual_sos → Ingest → raw_events → SOS → 服务端 deadline → 通知任务 → 投递结果 → App/Admin 展示全链路，逐层查实际数据及调用次数。

- 默认 60 秒倒计时、取消、立即求救、到期、重复触发、pending 中再次 manual_sos、终态后新事件、无联系人、重复手机号、通知部分失败、达到重试上限、事件坐标非法与位置快照回落。
- cancel/confirm/扫描同刻竞态；同设备多事件并发、同 eventId 重放、多台 App 同账号操作；旧单处置不污染新单。
- 后端真实进程在 deadline 前后退出/重启，验证恢复；可用缩短时间加速其他用例，但至少一条链路保留默认 60 秒。区分主动 tick 的单测与真实重启测试。
- 在“原始事件落库后、SOS 建单前”以及快照/副表写入期间注入故障。现有 Ingest 先保存 raw 再分发，重复 eventId 会跳过分发：重点证实原始数据存在是否仍可能漏建 SOS，以及重试、重启、回放是否真的恢复。
- 在“通知任务创建后”“占用一次发送尝试后”“Provider 已接收但 sent 尚未落库”分别注入中断/超时，验证漏发、重复发送和重试次数；同时触发直接 confirm 和扫描，验证通知并发行为。
- 区分 SOS 的 notified 状态、任务创建、Provider 接收成功和联系人实际收到；现有状态语义、UI/Push 文案若不一致要报告。没有服务商投递回执不能声称送达，更不能仅凭数据库计数宣称端到端 exactly-once。
- 设备换绑、账号注销、联系人变更与进行中 SOS 的交叉操作，核对归属、处置权限、联系人选取时点和通知结果。
- 明确区分“事件已经到服务器后手机断网/被杀”和“事件仍未经过手机上传”。后者受 BLE、手机、网络和 App 生命周期约束，不能承诺云端仍能凭空收到求救。

## 5. BLE 协议与手机中转

先标出已实现、占位、协议冲突和硬件阻塞。未实现的 GATT/解析器列为交付缺口；可用协议向量说明缺失行为，不用另写一套永远不进入产品的测试解析器冒充产品通过。

- 按 v0.6 验证 FEE0 服务、FEE1 Notify、FEE2 Write，扫描、真实 deviceId 核验、连接、握手、对时、订阅、断连与重连。
- 原始二进制帧 → envelope：小端、有符号字段、长度、非法/未知指令、七种事件映射、单位换算、WGS-84、无效哨兵、UTC=0、4 字节 Event_Seq、1 字节命令 Seq 的匹配与回绕。
- 由 deviceId + Event_Seq 构造 eventId 的稳定性、跨设备唯一性、头盔掉电与重传一致性；不得每次补传生成新 ID。
- 高危事件 1500ms ACK 超时、三次重试与 Flash 补传；头盔收 ACK 会擦除离线记录，重点检验 App 已 ACK 但尚未可靠落盘就被杀时的数据风险，以及磁盘写失败的处理。
- 按协议实际长度测试 MTU 协商失败或回落，交叉核对“4～25 字节”的摘要和实际事件长度；不能仅根据文档一句“无需分帧”免测。
- `ble-relay-uplink.ts` 当前队列上限 1000、批量上限 100、5 秒 flush：测 0/1/99/100/101 条、多设备公平性、溢出是否丢求救、毒事件与 401/404 是否阻塞其余设备。
- 测文件损坏、磁盘不足、持久化失败、恢复与新入队/flush 竞态、重复 start/stop、请求处理中退出登录、杀 App 后恢复，核对事件总数与身份隔离。
- A 账号有待传队列后退出，B 账号登录；设备解绑/转让后旧队列补传；环境切换后旧数据残留。查内存队列、持久化文件、命令 handled 集合与用户/设备归属。
- 下行命令必须分开测试 `__DEV__=true/false`。真实 executed success 需要头盔执行结果；开发模式模拟成功只能标记为模拟验证。

- 实时视频预览按决策 #37 查实现与阻塞。具备条件时测 SoftAP 连接、URL/鉴权、RTSP 播放、断流重连、前后台、退出资源释放、两端兼容；手机连无互联网热点时同时验证 SOS 上行和对讲可达性，并记录平台行为。
- 媒体元数据、事件关联、跨账号访问、预签名 URL 过期、对象不存在、超过 2GB 的 sizeBytes/BigInt 序列化；MockStorage 返回 URL 不代表真实对象可访问。
- Push/SMS/COS 的当前真实接入程度、缺失配置、失败/超时/重试及 Mock 回退可见性。客户端不得把 Mock 记录显示成真实送达或真实上传完成。

## 10. 管理后台浏览器验收

启动本地 Admin 和隔离后端，真实浏览器遍历登录、概览、用户、设备、设备详情、事故、事件。工具支持时自动化并保存关键截图/网络证据；缺工具则明确手工检查项。

- 登录失败与网络错误区分、token 过期/退出/浏览器返回、多标签页、未登录直接打开详情、无权限请求、刷新深层 URL。
- 搜索/清空、筛选组合、切换后分页重置、总数、首尾页、大数据、空结果、数据变化、并发点击和错误恢复。
- 概览数字与数据库/API 的口径一致；用户注销、绑定变更、在线阈值、事故状态、日期时区边界在各页面保持一致。
- 检查请求错误是否被渲染成“0”或“空列表”，避免后台把故障显示为正常无数据；收集 Console 与失败请求。
- 用户提供的昵称/设备名/事件字段包含 HTML、超长字符、换行时正确展示，无存储型/DOM 注入；键盘操作、小屏、大字体和可读性。
- 后端 admin e2e 通过、Admin 编译通过、浏览器业务操作通过是三种不同证据。

## 11. 数据库、部署、容量与可恢复性

- 空库全量 migration；从上一版本代表性测试数据升级；绑定历史回填、软删除、BigInt、唯一约束/外键/索引、事务回滚及重复部署一致性。只在隔离库操作。
- 高数据量轨迹/事件/后台查询检查分页与排序稳定性、N+1、查询计划、索引与连接池。不能把旧报告中的本机吞吐直接当线上容量。
- 针对接入、读接口、WS、设置回执、短信验证码和混合流量逐级升压；记录负载模型、持续时间、机器资源、p50/p95/p99、错误率、实际入库/通知数、内存/CPU/数据库连接和恢复表现。
- 大量普通位置事件中插入 SOS，测端到端告警延迟、队列排队与调度积压，确认紧急事件不会被普通流量长期阻塞。
- 有限时长稳定性与断网恢复测试；负载下降后观察内存/句柄/连接回落。没有产品 SLO 时明确本次参考阈值，不自行宣布“性能达标”。
- 对照 Dockerfile、Compose、Caddy、EMQX、环境变量模板检查构建、启动、迁移步骤、反向代理 REST/WS、SPA 路由、请求大小、代理信任、监听端口、TLS 与实际部署差异。
- 专用本地环境验证服务重启、依赖未就绪、配置缺失、优雅退出。备份恢复使用测试数据执行一次，说明恢复后计数/关系验证和可接受数据损失边界。
- 依赖漏洞与可达性、打包产物中的密钥/开发入口、日志脱敏、配置中 Mock/测试开关误入正式环境。必要时查官方漏洞源，工具不可用要报告，不能把 audit 未执行写成无漏洞。

## 12. 证据、报告与完成标准

持续维护报告，建议放在 `docs/testing/<本轮日期>/`，保留：

1. `REPORT.md`：版本与环境、执行概况、主要缺陷、交付结论、与旧报告的差异。
2. `COVERAGE_MATRIX.md`：模块/规则/实现/用例/平台/状态/证据映射，包含全部未测项。
3. `BUGS.md`：每项含 ID、严重度及理由、影响范围、前置数据、最小复现步骤或命令、预期/实际、源码位置、日志或截图、复现频率、建议修复及回归范围。
4. `DEVICE_CHECKLIST.md`：Android/iPhone 的逐步真机验收，列机型/系统/构建版本/硬件版本/操作/预期/实际；缺设备保持未测。
5. 本轮新增测试、可复跑脚本与脱敏证据。记录启动和清理方法，只清理本轮资源。

结果状态至少区分 PASS、FAIL、BLOCKED、NOT_RUN、OUT_OF_SCOPE，并额外标明证据来源：静态审计/单测/集成/真实进程/模拟器/真机/真实第三方。静态怀疑与已复现缺陷分开；未实现的本期功能与测试资源缺失分开。

对 9 月 10 日报告的缺陷逐项标记：当前复验通过、复发、未复验或按后续决策变更。不要照搬历史通过数。检查已有测试是否只是输出 console、只测 mock 调用或自我校验，必要时补行为断言。

任何高严重度发现先简短报告证据和影响，继续完成独立测试；不要因为发现第一个问题就结束。针对真正的缺口补有价值的测试，避免重复已有断言来凑数量。

最后逐项核对清单。可以结束的条件是：所有已盘点项目都有结果或明确阻塞、全部可执行测试已完成、失败有复现与影响说明、代码/测试变更有摘要、未清理资源有说明。仍有核心真机/第三方/实现缺口时，结论不能写“全部通过”“可以正式上线”或“没有任何问题”。

最终面向我用中文回答：当前版本实际测了什么；最严重的问题是什么；哪些只是模拟通过；哪些交付项缺失；还需要我提供哪些具体资源；下一步按影响优先处理什么。现在开始执行。
